# AUTHFORGE Milestone 4 Security Audit & Hardening Report (`v0.1.0-m4-p3`)

## 1. Executive Summary
Across **AUTHFORGE v0.1.0 Milestone 4** (`M4-P1`, `M4-P2`, and `M4-P3`), all identified security findings and hardening items have been remediated and verified:
- **M4-P1 (`M4-AUD-01` through `M4-AUD-08`)**: DNS pre-resolution and IP pinning (`M4-AUD-01`), request-budget `EX_AUTHZ` propagation across CLI and TUI (`M4-AUD-02`), authorization log deduplication (`M4-AUD-03`), multi-block HTTP header parser state reset (`M4-AUD-04`), IPv6 literal rejection (`M4-AUD-05`), `curl`/`openssl` proxy environment isolation (`M4-AUD-06`), `proto_probe_tls` `timeout` binary dependency check (`M4-AUD-07`), and TLS handshake failure / negotiation validation (`M4-AUD-08`).
- **M4-P3 (`M4-P3-A`, `M4-P3-B`, `M4-P3-C`)**:
  - **`M4-P3-A` (Missing `curl` Dependency)**: Updated `authz_safe_http` (`core/authz.sh`), `_pa_cmd_http_auth` (`modules/proto_audit.sh`), `_ai_cmd_scan` and `_ai_cmd_oidc_check` (`modules/auth_intel.sh`), and `_wa_fetch`, `_wa_cmd_headers`, `_wa_cmd_cookies`, and `_wa_cmd_rate_limit_check` (`modules/web_auth.sh`) to return `EX_DEPENDENCY` (`4`) while preserving `[NOT TESTED]` messages when `curl` is missing, and updated all TUI module menus (`mod_proto_audit_menu`, `mod_auth_intel_menu`, `mod_web_auth_menu`) to propagate `EX_DEPENDENCY` (`4`).
  - **`M4-P3-B` (Numeric IPv4 Validation)**: Updated `validate_ipv4`, added `validate_ipv4_ambiguous`, and hardened `validate_hostname` and `validate_target` (`core/validate.sh`) plus `authz_is_lab_target` and `authz_require_online` (`core/authz.sh`) to reject ambiguous legacy `inet_aton` numeric IPv4 representations (`0177.0.0.1`, `127.0.0.010`, `010.0.0.1`, `127.1`, `127.0.1`, `2130706433`, `0x7f.0.0.1`, `0x7f000001`, `127.0.0.0x1`, `127.00.0.1`, `1.2.3.4.5`) with `EX_VALIDATION` (`6`) before DNS resolution (`getent`) or scope comparison.
  - **`M4-P3-C` (Safe Launcher `scripts/authforge-safe.sh`)**: Added `scripts/authforge-safe.sh` to the build (`Makefile` `SRC`) and release archives, scrubbing `BASH_ENV`, `ENV`, `PROMPT_COMMAND`, `PS4`, `SHELLOPTS`, `BASHOPTS`, `GLOBIGNORE`, `CDPATH`, `FIGNORE`, `EXECIGNORE`, `HOSTFILE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `LD_DEBUG`, `LD_PROFILE`, `DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `FTP_PROXY`, `NO_PROXY`, `http_proxy`, `https_proxy`, `all_proxy`, `ftp_proxy`, `no_proxy`, `CURL_HOME`, `OPENSSL_CONF`, `OPENSSL_ENGINES`, `OPENSSL_MODULES`, and `BASH_FUNC_*` variables, and documented `bash scripts/authforge-safe.sh` (`BASH_ENV`) and `LD_PRELOAD` limitations in `README.md`, `SECURITY.md`, and `docs/ARCHITECTURE.md`.

The full test suite now comprises **871 passing tests** (`871 passed, 0 failed, 0 skipped`) across `53` syntax-verified shell files.

## 2. M4-P1 through M4-P3 Remediation Matrix

| ID | Severity | Finding / Task Summary | Affected Files | Remediation & Verification |
| :--- | :---: | :--- | :--- | :--- |
| **`M4-AUD-01`** | **Medium** | Hostnames were checked syntactically without pre-resolving DNS, verifying resolved IPs against lab ranges, or pinning the resolved IP in `curl`/`openssl`. | `core/authz.sh`, `lib/proto_audit.sh` | Added `authz_is_lab_ip` and `authz_resolve_target` (`core/authz.sh`). Pre-resolves hostnames before connection, verifies every resolved IP is in loopback or RFC1918 when `allow_nonlocal_targets=0`, rejects public, link-local, mixed, and malformed DNS answers with `EX_AUTHZ=5`, and pins the validated IPv4 address via `curl --resolve` and `openssl s_client -connect`. |
| **`M4-AUD-02`** | **Medium** | Request-budget exhaustion (`EX_AUTHZ=5`) was caught as a generic fetch error (`[NOT TESTED]`, exit `0`) or swallowed in TUI menus. | `modules/web_auth.sh`, `modules/proto_audit.sh`, `modules/auth_intel.sh`, `core/menu.sh`, `authforge.sh` | Propagated `EX_AUTHZ=5` and `EX_VALIDATION=6` immediately across all CLI and TUI callers. |
| **`M4-AUD-03`** | **Low** | Redundant `online authorization verified for target` log entries emitted per probe. | `core/authz.sh`, `modules/proto_audit.sh` | Deduplicated log emission per session+target via `_AN_AUTHZ_LAST_LOGGED` while running full validation/scope checks on every probe. |
| **`M4-AUD-04`** | **Low** | HTTP header parsers did not reset state across multi-block HTTP responses. | `lib/proto_audit.sh`, `lib/web_auth.sh`, `lib/auth_intel.sh` | Reset parser state whenever a new `^HTTP/[0-9.]+\ [0-9]{3}` status block begins. |
| **`M4-AUD-05`** | **Low** | Inconsistent IPv6 literal handling across validators and target checks. | `core/validate.sh`, `core/authz.sh`, `modules/proto_audit.sh` | Consistently rejected `::1`, `[::1]`, and colon/bracket host strings with `EX_VALIDATION=6`. |
| **`M4-AUD-06`** | **Medium** | Caller-controlled proxy environment variables could bypass `curl --resolve` IP pinning. | `core/authz.sh`, `lib/proto_audit.sh` | Added `--noproxy '*'` and scrubbed `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `http_proxy`, `https_proxy`, `all_proxy` (`NO_PROXY=*`). |
| **`M4-AUD-07`** | **Low** | Missing `timeout` dependency check in `proto_probe_tls`. | `lib/proto_audit.sh`, `modules/proto_audit.sh`, `core/deps.sh` | Checked `command -v timeout` in `proto_probe_tls` after `authz_resolve_target`, returning `EX_DEPENDENCY=4` and printing `[NOT TESTED] timeout not installed; TLS check skipped`. |
| **`M4-AUD-08`** | **Medium** | `proto_probe_tls` discarded `timeout`/`openssl` exit codes and `proto_parse_tls_output` accepted non-empty outputs without negotiated protocol/cipher. | `lib/proto_audit.sh`, `modules/proto_audit.sh` | Captured exit codes (`124` timeout, non-zero connect failures, empty output) and required valid negotiated SSL/TLS protocol and non-null cipher while reporting `REVIEW` for self-signed certificates when negotiation succeeds. |
| **`M4-P3-A`** | **Medium** | `curl`-dependent commands returned `0` instead of `EX_DEPENDENCY` (`4`) when `curl` was missing, and TUI menus did not propagate `EX_DEPENDENCY`. | `core/authz.sh`, `modules/proto_audit.sh`, `modules/auth_intel.sh`, `modules/web_auth.sh` | Checked `command -v curl` before request-budget consumption in `authz_safe_http`, returned `EX_DEPENDENCY=4` with `[NOT TESTED]` across all 6 `curl` subcommands (`proto-audit http-auth`, `auth-intel scan`, `auth-intel oidc-check`, `web-auth headers`, `web-auth cookies`, `web-auth rate-limit-check`), and propagated `EX_DEPENDENCY=4` through all TUI module menus. |
| **`M4-P3-B`** | **Medium** | Legacy numeric IPv4 representations (`0177.0.0.1`, `127.0.0.010`, `127.1`, `2130706433`, `0x7f.0.0.1`) could pass `validate_ipv4` or `validate_hostname` and be canonicalized by `getent`. | `core/validate.sh`, `core/authz.sh` | Enforced strict canonical decimal octets (no leading zeros) in `validate_ipv4`, added `validate_ipv4_ambiguous`, rejected numeric/hex TLDs and ambiguous IPv4 forms in `validate_hostname` and `validate_target`, and validated scope `target=` entries in `authz_require_online`. |
| **`M4-P3-C`** | **Low** | Safe launcher `scripts/authforge-safe.sh` needed in build/archive with complete documentation of removed variables, `bash scripts/authforge-safe.sh` (`BASH_ENV`), and `LD_PRELOAD` limitations. | `scripts/authforge-safe.sh`, `Makefile`, `README.md`, `SECURITY.md`, `docs/ARCHITECTURE.md` | Added `scripts/authforge-safe.sh` (`0755`) to `Makefile` `SRC` and archives, scrubbing 30+ environment variables and `BASH_FUNC_*` entries, with full documentation and regression tests. |
