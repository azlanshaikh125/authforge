# AUTHFORGE architecture (Milestone 5 — M5-P2)

## Layers
```
scripts/authforge-safe.sh  safe launcher: strips BASH_ENV/ENV/LD_PRELOAD/proxies/BASH_FUNC_* before exec
authforge.sh               entry: env sanitization, option parsing, bootstrap, dispatch, --fail-on exit logic
 ├─ core/                  framework (no module logic)
 │   constants  exit codes, severity/confidence vocab      log      structured logs + secret/hash/token redaction
 │   ui         colour/banner/progress/secret input        menu     multi-level TUI, honest status, authz/dep rc propagation
 │   errors     die/trap/cleanup registry                  tmp      private temp dir (0700), auto-clean
 │   validate   strict canonical IPv4/RFC-1123 validators  config   parsed key=value + profiles, backup/restore
 │   session    per-run 0700 report/evidence dirs + log    findings record model + JSON/CSV/MD/TXT export
 │   authz      fail-closed online gate, DNS pre-resolution & IP pinning, redirect & rate-limit enforcement
 │   plugin     safe module/plugin loader                  deps     dependency check + `doctor`
 ├─ scripts/               authforge-safe.sh (env-scrubbing launcher), install.sh, uninstall.sh
 ├─ data/                  compliance_mappings.dat (13-column TSV catalog: 40 controls across ASVS/NIST/CIS)
 ├─ lib/                   pure helpers: strutil, pwdcheck, hashid, wordlist, risk, mfa, session_audit, pwreset,
 │                         proto_audit, auth_intel, web_auth, compliance, evidence

 └─ tests/                 harness, unit (14 suites), integration (CLI, loopback socat, pty TUI), regression
```

## Milestone 4 Authorization, Validation & Environment Safety Controls (M4-P1 through M4-P3)
- **Fail-Closed Gate (`core/authz.sh`)**: Every online call passes `authz_require_online`, `authz_resolve_target`, and `authz_consume_request`. Missing `--allow-online`, missing/expired/mismatched `--scope FILE`, non-lab targets, or request-budget exhaustion exit `5` (`EX_AUTHZ`) across both CLI and TUI callers.
- **Strict Canonical Numeric IPv4 Policy (`core/validate.sh`, `core/authz.sh` — M4-P3)**:
  - `validate_ipv4` accepts only canonical 4-octet decimal IPv4 addresses (`0..255` per octet, with no leading zeros).
  - `validate_ipv4_ambiguous`, `validate_hostname`, and `validate_target` reject all legacy `inet_aton` numeric IPv4 representations before DNS resolution (`getent`), including octal leading-zero forms (`0177.0.0.1`, `127.0.0.010`, `010.0.0.1`), hexadecimal forms (`0x7f.0.0.1`, `0x7f000001`, `127.0.0.0x1`), 1/2/3-part shorthand (`127.1`, `127.0.1`), and 32-bit decimal integers (`2130706433`).
  - `validate_hostname` also rejects any string whose rightmost label is purely decimal digits or a hex literal, preventing resolver canonicalization from ever treating a hostname as an IPv4 literal. Both caller targets and `target=` entries in scope files are validated before comparison so validation and scope authorization cannot disagree.
- **DNS Pre-Resolution & IP Pinning (`M4-AUD-01`)**: `authz_resolve_target` resolves hostnames prior to connection, verifies every returned record is a canonical IPv4 address within loopback/RFC1918 lab ranges when `allow_nonlocal_targets=0` (rejecting public, link-local, mixed public/private, and malformed DNS answers), and pins the validated IPv4 address via `curl --resolve --noproxy '*'` and `openssl s_client -connect <pinned_ip>:<port> -servername <host>`.
- **Redirects, Timeouts & IPv6 Policy (`M4-AUD-04`, `M4-AUD-05`, `M4-AUD-08`)**: `authz_safe_http` disables automatic redirects (`--max-redirs 0`), resets header parsers on new HTTP status blocks, and enforces `online_connect_timeout_sec` and `online_max_time_sec`. `proto_probe_tls` captures `timeout` (`124`) and `openssl` exit codes and requires a valid negotiated protocol and non-null cipher. IPv6 target literals are unsupported and consistently rejected with `EX_VALIDATION=6`.
- **Fail-Closed Missing Dependency Handling (`M4-AUD-07`, M4-P3)**: Missing `curl`, `openssl`, `timeout`, or `getent` during online probes emit an explicit `[NOT TESTED]` explanation and return `EX_DEPENDENCY` (`4`) across all CLI subcommands (`proto-audit tls`, `proto-audit http-auth`, `auth-intel scan`, `auth-intel oidc-check`, `web-auth headers`, `web-auth cookies`, `web-auth rate-limit-check`) and propagate `EX_DEPENDENCY` (`4`) through all TUI submenus (`mod_proto_audit_menu`, `mod_auth_intel_menu`, `mod_web_auth_menu`) and `menu_main`.
- **Safe Launcher (`scripts/authforge-safe.sh` — M4-P3)**:
  - Invoking `./scripts/authforge-safe.sh [args...]` directly uses `#!/usr/bin/env -S env -u BASH_ENV -u ENV bash` so `BASH_ENV` and `ENV` are stripped before the launcher's Bash process starts, then scrubs `BASH_ENV`, `ENV`, `PROMPT_COMMAND`, `PS4`, `SHELLOPTS`, `BASHOPTS`, `GLOBIGNORE`, `CDPATH`, `FIGNORE`, `EXECIGNORE`, `HOSTFILE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `LD_DEBUG`, `LD_PROFILE`, `DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `FTP_PROXY`, `NO_PROXY`, `http_proxy`, `https_proxy`, `all_proxy`, `ftp_proxy`, `no_proxy`, `CURL_HOME`, `OPENSSL_CONF`, `OPENSSL_ENGINES`, `OPENSSL_MODULES`, and all `BASH_FUNC_*` variables before `exec`-ing `/bin/bash --noprofile --norc authforge.sh "$@"`.
  - **Limitations**: Running `bash scripts/authforge-safe.sh` does not protect against `BASH_ENV` being processed before the launcher starts because the caller's `bash` binary processes `BASH_ENV` during its own startup before reading the script. Similarly, if `LD_PRELOAD` or `LD_LIBRARY_PATH` is set in the parent process, the OS dynamic linker loads it into the launcher process at `execve()` time before script commands execute; to protect the launcher itself, invoke `env -u LD_PRELOAD -u LD_LIBRARY_PATH -u BASH_ENV -u ENV ./scripts/authforge-safe.sh`.
- **Correlation (`lib/risk.sh`)**: Adds `CORR-07` (weak/cleartext transport + cookie/session exposure) and `CORR-08` (missing rate-limit headers + weak password/MFA).

## Milestone 5 Compliance, Evidence & Installation Controls (M5-P1 & M5-P2)
- **Pinned 40-Control Compliance Engine (`data/compliance_mappings.dat`, `lib/compliance.sh`, `modules/compliance.sh`)**: Maps session check ledgers (`checks.dat`) and active findings (`findings.dat`) to `25` OWASP ASVS `5.0.0` controls, `11` NIST SP `800-63B-4` controls, and `4` CIS `v8.1` safeguards (`40` controls total). All 40 controls cap positive status at `PARTIAL` (`max_status=PARTIAL`). NIST `Sec.3.1.1.1`, `Sec.3.1.1.2`, and `Sec.3.2.5` evaluate conservatively to `PARTIAL` (or `NOT TESTED`), and untrusted `target_linked` / `verifier_behavior_established` tokens in `checks.dat` are stripped.
- **Session Containment & Kernel `flock` Check Ledger (`core/session.sh`)**: `_session_verify_droot_lexical`, `_session_verify_report_dirs`, and `_session_verify_evidence_dirs` enforce strict lexical, symlink, UID, mode (`0700`), and `..` `(dev,ino)` containment. `session_record_check` acquires an exclusive kernel lock via `flock` on `.checks.lock`, verifies descriptor identity via `/proc/${BASHPID}/fd/${lock_fd}`, and atomically updates `checks.dat`.
- **Fail-Closed Evidence & Verifiable Bundles (`lib/evidence.sh`, `modules/evidence.sh`)**: `evidence_manifest_update` writes via a same-directory temporary file and atomic `mv -f`. `evidence_manifest_verify` detects tampered, missing, or unlisted extra files across `reports/<sid>/` and `evidence/<sid>/`. `evidence_verify_bundle` validates archive entries pre-extraction before running `evidence_manifest_verify`.
- **Code (`AN_ROOT`) vs. Mutable Data (`AN_DATA_DIR`) Separation (`scripts/install.sh`, `scripts/uninstall.sh`, `authforge.sh`, `core/config.sh`)**: `install.sh` installs code into `LIBDIR` (`~/.local/share/authforge`) with `.authforge-install.manifest` (`format=authforge-install-manifest-v2`, recording `DIR <relpath> <octal-mode>` and `FILE <octal-mode> <sha256> <relpath>`) and initializes mutable user state in `DATADIR` (`~/.local/state/authforge`, mode `0700`). Both `install.sh` (when replacing an existing `LIBDIR`) and `uninstall.sh` enforce full manifest verification (all 8 header fields, all 10 runtime subdirectories with strict 3-digit octal directory mode validation (`^[0-7]{3}$`, rejecting 4-digit modes and `setuid`/`setgid`/`sticky` bits on both manifest and disk), exact mode matching in `v2`, and controlled migration from fully verified `v1` installations, all 12 core anchor files, relative path confinement, non-symlink checks, file modes, SHA-256 digests, and rejection of any unlisted/extra files). An unverified directory is never automatically replaced (`EX_VALIDATION=6`). `uninstall.sh` removes files via `rm -f` + `rmdir` and preserves `AN_DATA_DIR` unless `--purge-data` is passed.
