# AUTHFORGE Security Architecture & Threat Model

## 1. System Overview & Trust Boundaries

AUTHFORGE is an offline-first, Bash 5+ authentication security assessment framework with optional, strictly gated lab-only HTTP/TLS probes.

### Trust Boundaries
1. **Operator Process Boundary**: The invoking shell environment (`ENV`, `BASH_ENV`, `PATH`, `LD_PRELOAD`, `HTTP_PROXY`, `BASH_FUNC_*`) may contain untrusted or misconfigured variables.
2. **Analyzed Artifact Boundary**: Password lists, hash dumps, wordlists, configuration descriptors (`*.conf`), `Set-Cookie` headers, and external `.tar.gz` evidence bundles are treated as **untrusted data**, never executable code.
3. **Filesystem & Session Containment Boundary**: Session directories (`$AN_DATA_DIR/reports/<sid>`, `$AN_DATA_DIR/evidence/<sid>`) and installed code (`$AN_ROOT`) operate under a local POSIX same-UID / root ancestor trust model.
4. **Network Target Boundary**: Online checks (`proto-audit`, `auth-intel`, `web-auth`) are refused by default and restricted to explicitly scoped, canonical IPv4 / RFC-1123 lab targets.

## 2. Threat Matrix & Implemented Mitigations

| Threat ID | Threat Scenario | Attack Vector | Mitigation in AUTHFORGE |
|---|---|---|---|
| **TM-01** | **Secret & Credential Leakage** | Secrets passed on CLI (`ps` / `/proc/<pid>/cmdline`), leaked in logs, or written to `findings.dat`. | Interactive secrets are read via `ui_read_secret` (`read -rs`) or `stdin`; subprocesses receive data via pipes/tempfiles (`tests/regression/test_secret_hygiene.sh` verifies `argv` via shims); `log_redact` scrubs passwords, PHC/crypt/hex hashes, bearer tokens, cookies, and recovery codes. |
| **TM-02** | **Code Execution via Config or Descriptors** | Malicious `$(cmd)` or backticks inside `authforge.conf`, `*.profile`, or `sample-*.conf` descriptors. | Config and descriptor files are never `source`d or passed to `eval`; `_config_parse_file`, `mfa_parse_descriptor`, `sess_parse_descriptor`, and `pwr_parse_descriptor` enforce strict key whitelists and regex value validation (`core/config.sh:46-116`). |
| **TM-03** | **Environment & Hook Injection** | `BASH_ENV`, `ENV`, `PROMPT_COMMAND`, `CDPATH`, `BASH_FUNC_*`, or proxy overrides (`HTTP_PROXY`) hijacking execution. | `scripts/authforge-safe.sh` uses `#!/usr/bin/env -S env -u BASH_ENV -u ENV bash`, verifies `_SAFE_ROOT` and `authforge.sh` ownership and `((mode & 022) == 0)`, and `exec`s `/bin/bash --noprofile --norc` with scrubbed environment and `NO_PROXY="*"`. |
| **TM-04** | **SSRF, DNS Rebinding & Ambiguous IPv4 Bypass** | Scope bypass via octal/hex/dword IPv4 (`0177.0.0.1`, `2130706433`), IPv6 literals, public DNS records, or HTTP redirects. | `validate_ipv4`, `validate_ipv4_ambiguous`, and `validate_hostname` (`core/validate.sh`) reject non-canonical numeric IPv4 and IPv6 before `getent`; `authz_resolve_target` verifies all DNS A records are lab/RFC-1918 IPv4 and pins the resolved IP via `curl --resolve --max-redirs 0 --noproxy '*'`. |
| **TM-05** | **Session Directory Traversal & Lockfile Races** | Symlinked `.checks.lock`, `..` traversal in `AN_DATA_DIR`, or concurrent writers corrupting `checks.dat`. | `_session_verify_droot_lexical` and `_session_verify_report_dirs` (`core/session.sh`) reject `/`, trailing `/`, `//`, `.`, `..`, symlinks, and bad modes, verifying `..` `(dev,ino)` identity; `session_record_check` verifies `pre_lmeta == fd_lmeta == post_lmeta` via `/proc/$BASHPID/fd/$lock_fd` and acquires kernel `flock -x`. |
| **TM-06** | **Evidence Tampering & Malicious Bundle Archives** | Modifying `findings.dat`/`checks.dat`, injecting unlisted extra files, or supplying a `.tar.gz` bundle with `../` or symlinks. | `evidence_manifest_verify` hashes all session files and scans `reports/<sid>/` and `evidence/<sid>/` (`dotglob`) to reject unlisted extra files; `evidence_verify_bundle` inspects `tar -ztvf` pre-extraction to reject non-regular/non-dir entries, `..`, leading `/`, and unexpected paths. |
| **TM-07** | **Unsafe Install/Uninstall Deletion & Forged Manifest Overwrite** | Running `install.sh` or `uninstall.sh` against a directory containing unrelated files, modified directory/file permissions, or a forged/partial `.authforge-install.manifest`, or overwriting read-only `AN_ROOT` during `config restore`. | `install.sh` separates `AN_ROOT` from `AN_DATA_DIR` and writes `.authforge-install.manifest` (`format=authforge-install-manifest-v2` with `DIR <relpath> <octal-mode>` and `FILE <octal-mode> <sha256> <relpath>`); both `install.sh` (on existing `LIBDIR`) and `uninstall.sh` verify all 8 manifest headers, all 10 runtime directories (enforcing 3-digit octal modes `^[0-7]{3}$` with zero `setuid`/`setgid`/`sticky` bits, exact recorded octal directory modes in `v2`, and controlled migration from fully verified `v1` manifests), 12 core file anchors, relative path confinement, exact file modes, and every file's SHA-256 digest while rejecting any unlisted/extra files or symlinks (`EX_VALIDATION=6`, preserving unverified directories byte-for-byte); `uninstall.sh` removes files individually via `rm -f` + `rmdir` (never `rm -rf`) and preserves `AN_DATA_DIR` by default. |

## 3. Documented Security Boundaries & Residual Limitations

1. **Parent Process Dynamic Linker (`LD_PRELOAD`)**: If `LD_PRELOAD` or `LD_LIBRARY_PATH` is set in the caller's process before `./scripts/authforge-safe.sh` is invoked, `ld-linux.so` loads it into the initial `env`/`bash` process at `execve()` time before script commands run. Unset `LD_PRELOAD` in the parent (`env -u LD_PRELOAD -u LD_LIBRARY_PATH -u BASH_ENV -u ENV ./scripts/authforge-safe.sh`).
2. **Direct `bash scripts/authforge-safe.sh` Invocation**: Passing the script as an argument to `bash` bypasses the `#!` shebang, allowing the caller's `bash` to process `BASH_ENV` during startup.
3. **Same-UID / Ancestor Directory Trust Boundary**: POSIX user-space processes cannot prevent a concurrent process running under the **same UID** (or `root`) from modifying files owned by that UID or renaming ancestor directories above `$AN_DATA_DIR` between syscalls.
4. **Linux `/proc` Requirement for Check Ledger**: `session_record_check` requires `/proc/<BASHPID>/fd/<lock_fd>` to verify the opened lock descriptor inode and fails closed if `/proc` is unmounted.
